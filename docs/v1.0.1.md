# v1.0.1 — 128-bit FRI + multi-tenant UI + payer sandboxes + OpenTelemetry

Four parallel upgrades on top of the v1.0 GA baseline.

## 1. FRI: 25 queries (128-bit) + native Rust acceleration

- `_N_QUERIES` raised from **4 → 25** so the FRI low-degree test reaches
  ~128-bit conjectured security in the random-oracle model. Pure-Python
  prove time stays under ~50 ms per call.
- New `pa_guard/services/zkstark_native.py` is a single-file adapter that
  loads the optional **Rust + PyO3** extension (`zkstark_native`) when
  installed and transparently dispatches `poly_eval_domain`, `fri_fold`,
  and `merkle_root` to it. Without the wheel, the pure-Python path is
  untouched.
- Crate at [`native/zkstark-accel/`](../native/zkstark-accel/) — `cargo`
  + `maturin develop --release` gets local dev a ~10× speed-up.
- New benchmark script
  [`scripts/bench_fri.py`](../backend/scripts/bench_fri.py) prints
  per-call latency for both backends + the speedup factor.

All 23 FRI / zk-STARK tests still pass (the bump is a parameter change, not
a contract change).

## 2. Frontend multi-tenant UI

- `src/lib/tenant.tsx` exposes `<TenantProvider>` + `useTenant()`, persists
  the active tenant in `localStorage`, and bridges the API client so
  every request emits an `X-Tenant-Id` header.
- `src/components/tenant-switcher.tsx` is a compact dropdown wired into the
  topbar — swaps tenants, registers new ids, shows the live header.
- `src/app/admin/page.tsx` is a tenant-management page in the sidebar
  (active tenant, known tenants list, registration form).
- The dashboard pings `getAggregate()` whenever the active tenant changes
  so metrics are tenant-scoped immediately.
- `runPA()` auto-fills `meta.tenant_id` from the active tenant so the
  backend's header/body match check never fires accidentally.

## 3. Payer sandbox URLs + smoke-test script

- Every adapter gained an `*_base_url` setting (defaulting to its
  production URL) plus a global `payer_sandbox_mode` toggle.
- Each adapter logs `sandbox=<bool>` and `base_url=<url>` on every call so
  ops can confirm which environment historical traffic hit.
- New script
  [`scripts/payer_smoke_test.py`](../backend/scripts/payer_smoke_test.py)
  pings each configured adapter (Availity / CoverMyMeds / Surescripts /
  NHS Spine) with a synthetic, de-identified `PADocument`. Returns
  non-zero if any configured adapter fails.
- Per-payer onboarding doc:
  [`docs/payer-onboarding.md`](payer-onboarding.md).

## 4. OpenTelemetry observability

- `pa_guard/core/otel.py` is an optional-by-default OTel bootstrap.
  When `PAG_OTEL_ENABLED=true` and the `[otel]` extras are installed it:
  - sets up the OTLP gRPC exporter pointed at
    `PAG_OTEL_EXPORTER_OTLP_ENDPOINT` (default `http://localhost:4317`),
  - auto-instruments **FastAPI**, **SQLAlchemy**, **httpx**,
  - wraps every `BaseAgent.run` in an `agent.<AgentName>` span carrying
    the auto-generated KPIs as span attributes.
- No PHI is ever attached to a span — only service / agent names, KPIs,
  UUIDs, and codes.
- Privacy + sampling notes in
  [`docs/observability.md`](observability.md).

## Test + lint posture

- **154 backend tests** passing (up from 151).
- Ruff clean across `pa_guard`, `tests`, and `scripts`.
- The new OTel surface is exercised via no-op tests; the live exporter is
  covered by the integration suite once the optional extras are installed
  in CI.

# v1.0.4 — Concrete ML FHE pipeline + minisign release + OTel/Grafana SLO dashboard

All three follow-ons from v1.0.3, wired end-to-end and live-tested where
the local sandbox allows. **192 backend tests pass + 4 live-sandbox
skips**; ruff clean. The `/metrics` endpoint was exercised against a
running backend before commit; the SLO dashboard JSON was lint-checked
against the Grafana provisioning schema.

## 1. Concrete ML FHE circuit pipeline

`concrete-ml` caps at Python `< 3.13`, so the whole pipeline runs inside
a pinned container.

- `fhe-compile/Dockerfile` — Python 3.12 slim + `concrete-ml >= 1.9, < 2.0`
  + `brevitas >= 0.11` + `torch >= 2.4`. Bind-mounts the repo at `/work`
  so artifacts land at the runtime auto-loader's path.
- `fhe-compile/train_and_compile.py` — Brevitas QAT MLP
  (`QuantIdentity` + 2× `QuantLinear` with `QuantReLU`), trained on the
  same synthetic joint distribution the plaintext `denial_risk_model`
  saw, then compiled via `compile_brevitas_qat_model`. Logs train +
  compile latencies, accuracy on a held-out set, and a 32-sample
  plaintext-vs-FHE parity check.
- `fhe-compile/README.md` documents the activation flow:
  `docker run` → artifact lands at
  `backend/.fhe_cache/denial_risk_v0.compiled` → backend reload with
  `PAG_FHE_ENABLED=true` → `fhe-coverage` SLO moves from breached to met.

Tunables via env (`QUANT_BITS`, `CALIB_SIZE`, `TRAIN_SIZE`, `EPOCHS`,
`SEED`). Privacy: training uses synthetic data only; no PHI touches the
pipeline at any stage.

## 2. Minisign-signed release manifest pipeline

- `backend/pa_guard/security/minisign.py` — pure-Python verifier for
  both hashed (`ED`) and legacy (`Ed`) minisign signatures, built on
  `cryptography.ed25519`. Parses the standard `untrusted comment:` /
  `trusted comment:` blob format, key id matching, and the global
  signature over `signature ‖ trusted_comment`.
- `backend/pa_guard/security/__init__.py` — package init.
- `backend/scripts/publish_release_manifest.py` — invoked by the CI
  release job after every Tauri matrix build:
  1. For each `target=path` pair, signs the artifact via the offline
     `minisign -SH` CLI (production keys live on a yubikey / HSM).
  2. Locally re-verifies each signature against the pubkey before
     publishing — fails closed if anything mismatches.
  3. Writes `data/desktop-updates.json` with version + sha256 + signature
     + URL for every platform.
- `ci/ci.yml.template` adds the `desktop-updates-manifest` job:
  downloads tauri artifacts, installs minisign, writes secret + pubkey
  to disk, runs `publish_release_manifest`, and uploads the resulting
  manifest as a release artifact.
- 11 tests pin verifier behaviour: hashed/legacy roundtrip, tamper
  rejection across payload + key id + global sig + algo, full blob
  parse + verify.

## 3. OTel collector + Grafana SLO dashboard

A complete observability profile boots with one command:

```bash
docker compose --profile observability up -d
```

Stack:

| Container | Image | Port | Purpose |
|---|---|---|---|
| `otel` | `otel/opentelemetry-collector-contrib:0.114.0` | 4317/4318/8888 | OTLP receiver + fan-out + PII strip processor |
| `tempo` | `grafana/tempo:2.6.0` | 3200 | Distributed traces backend |
| `prometheus` | `prom/prometheus:v3.0.0` | 9090 | Metrics store + remote-write receiver |
| `grafana` | `grafana/grafana:11.3.0` | **3001** | UI; SLO dashboard auto-provisioned |

Backend additions:

- `backend/pa_guard/api/metrics.py` — `/metrics` exposes the
  `OutcomeLogger` aggregate + the live `SloSnapshot` in standard
  Prometheus text format. Live test (after one submitted PA):
  ```
  pa_guard_sample_count 9
  pa_guard_agent_avg_latency_ms{agent="IntakeAgent"} 0.0067
  pa_guard_agent_avg_latency_ms{agent="SubmissionAgent"} 0.6096
  pa_guard_slo_overall_status 2
  pa_guard_slo_burn{slo_id="fhe-coverage"} 1.0
  ```
- `deploy/observability/otel-collector/config.yaml` — OTLP receivers,
  batch + memory limiter + an `attributes/strip_pii` processor that
  drops any span attribute whose name suggests free text
  (defense-in-depth, even though the backend never attaches PHI).
- `deploy/observability/tempo/tempo.yaml` — single-binary Tempo with
  local block storage; production swaps the backend to S3/GCS.
- `deploy/observability/prometheus/prometheus.yml` — scrapes the
  backend `/metrics` + the collector's self-metrics.
- `deploy/observability/grafana/provisioning/datasources.yaml` —
  registers Prometheus + Tempo.
- `deploy/observability/grafana/provisioning/dashboards.yaml` — mounts
  the PriorAuthGuard dashboards folder.
- `deploy/observability/grafana/dashboards/slo.json` — SLO dashboard:
  - Stat panel: overall SLO status (green / yellow / red).
  - Stat panel: denial rate.
  - Stat panel: FHE-executed share.
  - Table: per-SLO target / actual / burn / status (joined by `slo_id`).
  - Time series: per-agent avg latency.
  - Time series: per-agent success rate.
  - Time series: error-budget burn across all SLOs.

Verified live against the actual backend — every metric the dashboard
queries exists and labels resolve correctly.

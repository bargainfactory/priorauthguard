# v1.0.3 — SQL filter push-down + trained denial model + auto-updater + Playwright E2E

Four follow-on workstreams from v1.0.2, all wired end-to-end. **179 backend
tests pass + 4 live-sandbox skips**; ruff clean. Backend smoke-tested
against a running uvicorn process for each new surface.

## 1. PA list filter push-down

`GET /v1/pa?status=…&urgency=…&payer_id=…` no longer over-fetches and
post-filters in Python. The new `PAListFilters` dataclass flows into
`PARegistry.list_recent`, and `SqlPARegistry` translates each predicate
to a dialect-aware JSON-path expression:

| Filter | Postgres | SQLite |
|---|---|---|
| `status` | `payload->>'status' = :status` | `json_extract(payload, '$.status') = :status` |
| `urgency` | `payload->'pa_request'->'meta'->>'urgency' = :urgency` | `json_extract(payload, '$.pa_request.meta.urgency') = :urgency` |
| `payer_id` | `payload->'pa_request'->'meta'->>'payer_id' = :payer_id` | `json_extract(payload, '$.pa_request.meta.payer_id') = :payer_id` |

`InMemoryPARegistry` keeps the same semantics for tests + dev. Live
smoke test (`X-Tenant-Id: smoke`, one anthem PA): `payer_id=anthem` → 1
row, `payer_id=uhc` → 0, cross-tenant read → 0.

## 2. Trained denial-prediction model

`pa_guard/services/denial_risk_model.py` now ships a real
**logistic regression** trained on synthetic data whose joint distribution
mirrors what the FHE calibration set
(`fhe_pipeline._synth_calibration`) uses. The model is fitted by
gradient descent on a 4000-sample synthetic corpus, persisted at
`pa_guard/services/denial_risk_v1.weights.json`, and consumed at
inference time by `_DenialRiskBaseline` — no sklearn / torch needed
at request time.

| Feature | Coefficient |
|---|---|
| `urgency` | 0.965 |
| `prior_denials` | 0.606 |
| `missing_docs_count` | 0.824 |
| `bias` | -1.373 |

Verified with live PA traffic: routine + 0 denials + 0 missing docs →
prediction ≈ 0.20 (was 0.10 under the heuristic). Monotonic in all three
features; the trained baseline shares the exact same `_featurize`
function as the Brevitas-QAT FHE circuit so plaintext and FHE outputs
stay aligned.

Training is reproducible from `python scripts/train_denial_risk.py`.

## 3. Tauri auto-updater

- `tauri-plugin-updater = 2.0` added to `src-tauri/Cargo.toml`.
- `tauri.conf.json` gains a `plugins.updater` block with two endpoints
  (production CDN + loopback dev), the `dialog: true` user prompt, and
  a `pubkey` placeholder for ops to paste the minisign public key.
- New Rust command `check_for_update` in `src-tauri/src/lib.rs` exposes
  the updater plugin to the frontend so a menu/button can trigger a
  check on demand.
- Backend serves the manifest at
  `GET /v1/updates/desktop/{target}/{current_version}`:
  - Returns **204** when no manifest exists, the current is already at
    or above latest, or the target isn't bundled.
  - Returns **200** with a Tauri-format JSON body listing the matching
    platform's signature + download URL.
- Manifest path is config-driven (`PAG_UPDATE_MANIFEST_PATH`,
  default `data/desktop-updates.json`).
- Tests pin: no-manifest → 204, older current → 200, equal → 204,
  newer than latest → 204, missing target → 204, HEAD probe matches
  body presence.

## 4. Playwright end-to-end

- `frontend/playwright.config.ts` with a global setup that polls
  `/readyz` on the backend before starting tests.
- `tests-e2e/specs/happy-path.spec.ts` covers:
  1. Dashboard renders with `PrivacyFHEPanel`.
  2. Switch tenant via the topbar dropdown.
  3. Submit a PA from `/intake`.
  4. Land on `/pa/[rid]`, confirm no PHI in any visible text.
  5. Navigate to `/pa`, confirm the new run is there and filterable
     by payer.
  6. Navigate to `/slo`, confirm the snapshot renders.
- `frontend/package.json` gains `@playwright/test` + `e2e` / `e2e:install`
  scripts.
- New CI job `e2e` in `ci/ci.yml.template`: boots the backend with
  uvicorn, waits on `/readyz`, runs `pnpm e2e` against the Next dev
  server; uploads the Playwright HTML report on failure.
- Playwright artifacts (`playwright-report/`, `test-results/`) added to
  `frontend/.gitignore`.

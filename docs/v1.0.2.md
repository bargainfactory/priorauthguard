# v1.0.2 — full Rust FRI, PA list + SLO dashboard, live payer sandbox suite

Four parallel upgrades on top of v1.0.1.

## 1. Full Rust FRI prover + verifier

[`native/zkstark-accel/src/lib.rs`](../native/zkstark-accel/src/lib.rs) now
exposes the complete proof lifecycle natively:

- `prove(model_commitment, input_hash, output_hash) → bytes`
- `verify(model_commitment, input_hash, output_hash, proof_blob) → bool`

The Rust implementation reuses the same Goldilocks field, the same
domain-separated BLAKE2b Merkle layout, the same Fiat-Shamir transcript
byte protocol, and the same `PAGF1` serialization format the Python prover
already speaks — so the two backends produce **byte-for-byte identical
proofs**. The Python `ZkStarkProver.prove` and `ZkStarkVerifier.verify`
short-circuit into the native path when the wheel is installed; tests pass
identically against either backend.

Self-test inside the crate (`zkstark_native._selftest`) sanity-checks the
field, primitive roots, and polynomial construction. CI runs it on every
platform's wheel.

## 2. Backend SLO endpoint + PA list filters

- New [`SloEvaluator`](../backend/pa_guard/services/slo.py) consumes the
  existing `OutcomeAggregate` and produces an `SloSnapshot` with:
  - `denial-rate` (≤ 20%)
  - `pipeline-latency-p99` (≤ 5 s)
  - `fhe-coverage` (≥ 80%)
  - `voice-on-device` (≥ 95%)
  - `agent-success-rate` (≥ 95%)
- Targets are tunable via `PAG_SLO_*` settings.
- New endpoint `GET /v1/slo/snapshot?window_seconds=N`.
- `GET /v1/pa` now accepts `status`, `urgency`, `payer_id` query params —
  scoped to the active tenant via `X-Tenant-Id`.

## 3. Frontend `/pa` + `/slo` pages

- [`/pa`](../frontend/src/app/pa/page.tsx) — recent PA runs for the active
  tenant with status / urgency / payer filters and inline risk + audit
  badges. Tenant-scoped automatically.
- [`/slo`](../frontend/src/app/slo/page.tsx) — SLO compliance card grid
  with a per-target budget-burn bar that turns amber at "at-risk" and red
  at "breached". Overall status chip at the top.
- Sidebar gains `PA runs` and `SLOs` entries.

## 4. Live payer sandbox integration tests

- New marker `live_sandbox` and folder
  [`backend/tests/integration/`](../backend/tests/integration/).
- Tests skip cleanly unless `PAG_RUN_LIVE_SANDBOX_TESTS=true` AND the
  per-payer credentials are present.
- Per-adapter test: Availity, CoverMyMeds, Surescripts, NHS Spine. Each
  constructs the adapter the same way the FastAPI lifespan does, submits
  a synthetic de-identified `PADocument`, and asserts a 2xx with a
  `confirmation_code`.
- CI adds a manual `workflow_dispatch` `live-sandbox` job that pulls the
  credentials from GitHub Actions secrets and runs the marker.

## 5. CI additions

- `zkstark-native` job: builds the maturin wheel on Linux + macOS-x64 +
  macOS-arm + Windows, self-tests the wheel (`prove` + `verify` + tamper
  rejection), uploads wheels on tag.
- `live-sandbox` job: manual-only (`workflow_dispatch`); runs the live
  sandbox suite against provisioned secrets.

## Test + lint posture

- **167 backend tests** passing (up from 154); 4 live-sandbox tests skip.
- Ruff clean across `pa_guard`, `tests`, `scripts`.
